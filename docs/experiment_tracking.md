# Experiment Tracking

## Organization

Experiment templates live under `validation/experiments/`.

Current templates:

- `retrieval_baselines.yaml`
- `recommendation_baselines.yaml`
- `sequence_baselines.yaml`
- `ranking_baselines.yaml`
- `llm_query_understanding.yaml`
- `multimodal_baselines.yaml`
- `genrec_baselines.yaml`
- `stage5_debug_validation.yaml`

## Result CSVs

Result files live under `validation/results/`.

Current result files:

- `retrieval_results.csv`
- `recommender_baselines.csv`
- `sequence_results.csv`
- `ranking_results.csv`
- `llm_query_understanding_results.csv`
- `user_profile_results.csv`
- `multimodal_results.csv`
- `genrec_results.csv`
- `final_leaderboard.csv`

Future result files can be added without changing current result files:

- real-LLM GenRec ablation CSVs can be added with distinct filenames or config paths

## Final Leaderboard

`validation/results/final_leaderboard.csv` is generated by:

```bash
python3 src/pipelines/generate_validation_report.py --config validation/experiments/stage5_debug_validation.yaml
```

The report generator normalizes existing component result CSVs into one shared schema.
When `sequence_results.csv` exists, sequence-model rows are included too.
When `ranking_results.csv` exists, ranking rows are included too.
When `llm_query_understanding_results.csv` exists, query-understanding rows are included too.
When `multimodal_results.csv` exists, text/metadata representation rows are included too.
When `genrec_results.csv` exists, GenRec rows are included too.

## Report Generation

Generated reports live under `validation/reports/`:

- `final_model_selection_report.md`
- `latency_quality_tradeoff.md`
- `validation_summary.md`
- `final_llm_decision.md`

## Naming Conventions

- Configs should end in `_debug.yaml` until real datasets are introduced.
- Result CSVs should be named by stage or component.
- Report filenames should describe the decision or view they support.

## Required Columns For Future Result CSVs

Future stages should provide:

- method
- split
- number of evaluated examples
- primary metric
- secondary metric
- coverage or diversity metric when applicable
- average latency
- p95 latency
- config path

## Adding A New Experiment

1. Add a config under the relevant `configs/` folder.
2. Add or update a template under `validation/experiments/`.
3. Run the pipeline that writes a result CSV under `validation/results/`.
4. Add a normalizer in `src/evaluation/report.py` only if the result schema is new.
5. Rerun validation report generation.

## Future Real-LLM Experiments

Add a new GenRec config with a different provider/model and keep
`allow_external_api_calls: false` unless intentionally running outside tests.
The result row can be appended to `genrec_results.csv` without changing the
leaderboard code as long as it keeps the GenRec result columns.
